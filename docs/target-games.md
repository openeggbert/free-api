# Free API — Target Games

Free API exists to serve exactly two games. This document describes each,
where it lives, and how it consumes Free API. See [`docs/scope.md`](scope.md)
for the scope policy and [`plan.md`](../plan.md) for the full evidence-based
usage audit.

## Free Eggbert

* Repo: `../free-eggbert` (a port of "Speedy Eggbert 2" / "Speedy Blupi").
* Top-level CMake project name: `SPEEDY_BLUPI_WINDOWS`.
* Links `free-api` and `free-direct` as sibling source subdirectories
  (`add_subdirectory(../free-api ...)`, `add_subdirectory(../free-direct ...)`)
  — this is its actual, current build, not a hypothetical future integration.
* Backend: `SPEEDY_BLUPI_BACKEND=FREEDIRECT` (DirectDraw/DirectSound/
  DirectPlay emulated by `free-direct` on top of SDL3; the only supported
  backend).
* Live frame-pump mechanism: `timeSetEvent`/`timeKillEvent` (a WinMM
  multimedia timer). Its `SetTimer`/`WM_TIMER` call sites are dead code
  (`MMTIMER` is hardcoded `TRUE`).
* Joystick input (`joyGetPosEx`/`joyGetNumDevs`) is used, live, per-frame,
  but only as an optional control scheme selectable in its options menu —
  free-api's current safe-stub (0 devices reported) degrades gracefully to
  keyboard/mouse.
* Own docs: `../free-eggbert/README.md`, `../free-eggbert/TODO.md`.

## Planet Blupi

* Repo: `../planetblupi`.
* Top-level CMake project name: `PLANET_BLUPI_WINDOWS`.
* Links `free-api` and `free-direct` the same way as Free Eggbert.
* Backend: `PLANET_BLUPI_BACKEND=FREEDIRECT`, same DirectDraw/DirectSound
  emulation model.
* Live frame-pump mechanism: `SetTimer`/`KillTimer`/`WM_TIMER` (real Win32
  timer messages, generated by Free API while the message loop polls
  `PeekMessage`/`GetMessage`). Never calls `timeSetEvent`.
* No joystick code at all (confirmed zero usage).
* Own docs: `../planetblupi/README.md`.

## Why this split matters for Free API's implementation

Both games share the same original "Blupi" heritage (near-identical
`CMovie`/`CEvent` class shapes, matching resource ID conventions, etc.), but
they are **not interchangeable** when it comes to which Free API code paths
are actually load-bearing:

* Each game uses a **different** live timer mechanism (see above) — both
  must keep working, since each is the *sole* frame-pump for one game.
* Each has its **own** `resource/*.rc` `STRINGTABLE` data (extracted at
  build time by `cmake/ExtractStringTable.cmake` for `LoadStringA`) — the
  same numeric ID can mean a completely different string in each game.
* Only Free Eggbert uses the joystick subset.
* Both games are always siblings of Free API and of *each other* on a
  normal development machine — never assume "which sibling directory
  exists" tells you which game is actually driving a given build. Free
  API's own `CMakeLists.txt` keys off `CMAKE_PROJECT_NAME` (the actual
  top-level project) for exactly this reason; see `docs/cmake-options.md`.
* Both games need a **SoundFont (`.sf2`) file present** for audible MIDI
  music (background music otherwise plays silently, which is not an error —
  see the README's "SoundFont requirement" section under "MIDI / MCI Music"
  for the exact lookup order and how to supply one).
